1. Project Overview

TrendPilot takes a topic, platform, writing tone, and output type, then produces social content through a local Ollama-backed workflow. It plans tool steps, researches content angles, writes a caption, generates hashtags, scores and reviews the draft, optionally creates a short-video script and title/thumbnail, then saves the result.

Important scope: TrendPilot generates content angles locally; it does not fetch or verify real-time social-media trends. Generated factual claims still need human verification.

3. Agent Workflow and Tools

  1. User submits topic, platform, tone, and output type.
  2. Planner creates a short execution plan using Ollama.
  3. Trend-idea tool creates five angles; the hashtag tool produces platform-aware tags.
  4. Caption writer follows platform and tone instructions.
  5. Content analyzer scores relevance, length, hashtags, CTA, readability, and originality.
  6. AI reviewer evaluates the draft; feedback can trigger up to the configured number of revisions.
  7. Optional reel/video script and title/thumbnail are generated according to output type.
  8. Memory and file saver persist the final Markdown and JSON results; the UI and CLI return the result.

Tool names are logged during execution. The planner’s steps are deterministic and the model supplies their topic-specific purposes; the workflow is not an autonomous tool-selection framework.

4. Testing and Changes

The project contains 10 assignment scenarios, 81 memory-history records, and 64 saved JSON/Markdown output pairs. The historical 10-case report shows all ten as approved with 100/100, but those results predate the output-contract checks added in this audit and should not be treated as proof that all outputs are perfect.

A live local run for “YOLOv8 helmet detection project” (LinkedIn, Professional, Post + Reel Script) produced and saved both outputs. It exposed two scoring bugs: the caption writer included a reel script that was also generated separately, so the analyzer counted both sections as 296 words; and the analyzer did not recognize the caption’s valid “Explore how...” call to action. The workflow now extracts and scores only the post, preserves hashtags, and recognizes “explore” as an action. Re-scoring the saved run yields a 134-word caption and 100/100 under the rule-based rubric, with 100% topic relevance. This is a rubric score, not a guarantee of factual accuracy or virality; the report screenshots show the original run that exposed these bugs.

Changes made during the audit:

  • Normalize assignment labels (“Reel script”, “Video script”, “Short post”, etc.) to supported output modes.
  • Require the test runner to check requested captions/scripts and verify saved-file paths.
  • Make the generator mention the requested topic early to improve topic specificity.
  • Fix topic alias matching for “AI Education” and false formatting flags on ordinary words/hashtags.
  • Preserve CamelCase hashtag text while deduplicating case-insensitively.
  • Separate the social post from a bundled reel script before analysis and recognize an “Explore how...” action as a valid CTA.
  • Add the Streamlit full-result save/download control and show the server-side saved path.

Focused regression tests: python -m unittest test_content_analyzer test_main_output_types. Historical failures and fixes are listed in tests/error_analysis.md.

5. Failure Analysis Summary

Five historical weak outputs ranged from 65 to 76 points. Observed causes included missing topic terms or CTA, platform length mismatch, a misspelled topic, unrecognized CamelCase hashtags, an unsupported topic alias, and false-positive formatting rules. The analyzer/prompt/test-runner fixes are recorded with source output files in tests/error_analysis.md. Hashtag semantic matching remains heuristic, and the person submitting the project should manually review model claims and outputs.
